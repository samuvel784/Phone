## Recommended route: a `gh-pages` branch containing only the policy

A Pages site is served from one branch and one folder. Using a dedicated `gh-pages` branch means
the published site contains **only** the privacy policy:

- no Kotlin/Java source, Gradle files, signing configuration, or internal notes are served;
- no internal documents (for example `docs/PLAY_RELEASE_CHECKLIST.md`) become web pages;
- `main` stays the development branch and is not itself published as the site;
- the published surface stays separate from the source tree. If the repository's visibility
  changes, re-check Pages availability and use the fallback described below.

Trade-offs:

| Route | What is published | Maintenance | Verdict |
|---|---|---|---|
| `gh-pages` branch, root folder | only `index.md` + `_config.yml` | one extra branch, regenerated by the script | **recommended** |
| `main`, `/docs` folder | every file in `docs/` | none extra, but internal docs go public and any future file added to `docs/` is published automatically | avoid |
| Separate policy-only repository | only the policy | a second repository to keep in sync | fallback if the main repository becomes private (GitHub Free does not publish Pages from private repositories) |

A policy-only repository does **not** expose project source; its only downside is duplicated
maintenance. The `gh-pages` branch avoids that while keeping the site just as narrow.

## Exact steps

### 1. Generate the site (local, no network)

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\prepare_privacy_pages.ps1
```

This writes (and overwrites) two files under the git-ignored `build/privacy-pages/` folder:

- `index.md` — `PRIVACY.md` with the YAML front matter Jekyll requires;
- `_config.yml` — the site title and the built-in `jekyll-theme-minimal` theme.

Re-run this script whenever `PRIVACY.md` changes, so the published page cannot drift from the
policy in the repository.

### 2. Push those two files to a new `gh-pages` branch

The following uses a throw-away Git repository in the temp folder. It leaves the working tree and
the `main` branch untouched, and creates a `gh-pages` history that contains only the policy.

```powershell
$pages = Join-Path $env:TEMP 'novadialer-pages'
Remove-Item -Recurse -Force $pages -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Path $pages | Out-Null
Copy-Item .\build\privacy-pages\index.md,.\build\privacy-pages\_config.yml $pages

git -C $pages init -b gh-pages
git -C $pages add index.md _config.yml
git -C $pages commit -m "Publish Nova Dialer privacy policy"
git -C $pages remote add origin https://github.com/samuvel784/NovaDialer.git
git -C $pages push -u origin gh-pages
```

Do not run the final `git push` until publication is authorized. Pushing a public branch is
publication.

If a `gh-pages` branch already exists later, repeat steps 1–2 and push the new commit to it (the
history is intentionally independent of `main`; no force-push is needed for normal updates).

### 3. Enable GitHub Pages

In the repository on GitHub:

1. **Settings** → **Pages**.
2. Under **Build and deployment**, set **Source** to **Deploy from a branch**.
3. Set **Branch** to `gh-pages` and **Folder** to `/ (root)`.
4. Press **Save**.

GitHub builds the Jekyll site and reports the deployment under **Actions** (or the Pages banner).

### 4. Public URL

```text
https://samuvel784.github.io/NovaDialer/
```

Put exactly this URL into Play Console → **App content** → **Privacy policy** only after step 5
passes.

### 5. Verify before claiming publication

- The page opens over **HTTPS** without signing in and without a certificate warning.
- The heading reads **Nova Dialer Privacy Policy** and the date matches `PRIVACY.md`.
- All sections (1–11) are present, including contacts, call history, backups, permissions and
  deletion. The page must not claim recording, SOS-location or other deferred functionality.
- The page source contains only the policy and theme assets — no application source, no
  `local.properties`, no keystore references.
- `curl.exe -I https://samuvel784.github.io/NovaDialer/` returns `HTTP/2 200` (or `HTTP/1.1 200`).
- Re-run the generator after any policy edit and confirm the live page changed.
